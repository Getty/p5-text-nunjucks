# Text::Nunjucks

A faithful Perl port of Mozilla's [Nunjucks](https://mozilla.github.io/nunjucks/)
templating engine: the same templates, the same context and the same options give
the same output, byte for byte, and the same error messages as Nunjucks v3.2.4.
Perl 5.40 or newer, Moo.

## Status: release 0.001

Ported and tested: the whole template pipeline (lexer, parser, compiler,
runtime), the `Environment`, the built-in filters, the `is` tests and the globals
(`range`, `cycler`, `joiner`), and the loaders (base `Loader`, `FileSystem`,
`Precompiled`). The upstream test suites are ported to `t/upstream/`; where one
test cannot pass yet it is a TODO that names its card.

**The entry point is `Text::Nunjucks::Environment`.** The top-level API of
Nunjucks' `index.js` (package-level `configure`, `render`, `compile`,
`render_string`) is not in 0.001.

```perl
use Text::Nunjucks::Environment;

my $env = Text::Nunjucks::Environment->new( [], { trimBlocks => 1 } );
print $env->render_string( "Hello {{ name | title }}", { name => 'world' } );
```

Not in 0.001: jinja-compat, `precompile` and its CLI, `NodeResolveLoader`,
`WebLoader`, chokidar `watch`, the browser bundles.

**Platform: POSIX only.** Paths follow node's POSIX `path`; Windows is not
supported and the test suite is expected to fail there.

**Differences from Nunjucks.** What differs on purpose, and every known open
difference, is listed in the `DIFFERENCES FROM NUNJUCKS`, `LIMITATIONS` and
`SECURITY` sections of the `Text::Nunjucks` POD. Each decision is an ADR in
[`docs/adr/`](docs/adr/). Read `SECURITY` before you pass template names you do
not control to the `FileSystem` loader.

## Development

```bash
maint/fetch-upstream          # pinned upstream checkout -> upstream/ (needs node)
echo '{"template":"{{ 1/3 }}"}' | node maint/oracle.js   # what does upstream do?
prove -lr t/                  # the suite; -r is mandatory (t/upstream/ is a subdirectory)
prove -l xt/                  # author checks, need node and upstream/
```

The shipped suite needs no node: the expected values of the corpus in `t/corpus/`
were generated by the oracle and are committed. The oracle (`maint/oracle.js`)
runs the real upstream and is correct by definition (ADR 0004).
